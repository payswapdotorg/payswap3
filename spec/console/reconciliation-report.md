## 3. Residuals — the honest gaps that remain at closure preparation

1. **In-memory developer stores are non-durable.** API keys, webhook endpoints, creation receipts, the request-log ring, and the audit trail are module-scoped in-memory state (the recorded design §11 ruling, `spec/console/PC-005-evidence.md`): cleared on process restart, per-process in any multi-instance deployment, and the audit trail is not tamper-evident durable evidence. The UI states this provenance honestly; the durable externalization is future governed work.
2. **DEP-008 release-record orphan (retained, NOT console-caused).** `scripts/test_production_readiness.mjs` retains exactly the recorded known base-failure signature (proof:release-identity #32 — the release record freezes revision `ed673d7`, orphaned by PR #39's squash-merge). Recorded post-closure backlog with an owner; PC-007 records its continued presence and does not fix it.
3. **Production/provider binding NOT CONNECTED (GitHub only).** The machine-recorded truth (`deploy/contracts/console-provider-bindings.json`, enforced by `scripts/test_console_deployment.mjs`): github CONNECTED as CI-hosting truth only; vercel/database/queue/cloudflare/observability UNBOUND with explicit nulls and the live-evidence-before-production-claim requirement. The PC-007 smoke is a local loopback verification of the composed repository application — NOT a production claim.
4. **Payments list has no per-role filter at the port level.** `listSessionIntents()` exposes no per-role list filter (its scope is the port's own runtime scope); the console records this honestly in the DTO `scopeNote`, and per-reference data-level role checks apply on the detail read (the queue authority's viewer-role check). Recorded in the reconciliation matrix and live-proven by the scope note rendering.
5. **No listing reads for queues/executions/reconciliation-runs/UNKNOWN-cases/clearing-netting/incidents.** The six operations modules render the health authority's domain answer plus an honest gap panel; they do not enumerate operational records (no such read is exposed at this baseline). Live-proven by the gap panels on every operations page.
6. **No merchant-decision command surface (area-20, RTN wave 2) and no webhook delivery worker.** `submitDecision` fails closed with the recorded reason; webhook endpoints are registered only, with the honest delivery-state note. Recorded in PC-003/PC-005 evidence.
7. **Administrator default access is fail-closed.** Only `/console` (overview) and the accounts cross-role views + documentation are administrator-reachable; nothing wider is explicitly authorized at this baseline (design §6) — widening requires a governed change. Live-proven by the journey 5 deny cells for administrator.
