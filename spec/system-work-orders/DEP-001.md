# DEP-001 — Deployment topology and environment contract

**Status:** MERGED — 50275dc (PR #7)
**Depends on:** protocol WORK-001..WORK-033 complete; product foundation present
**Owned surfaces:** deployment manifests, environment contracts, runtime topology documentation/configuration
**Forbidden:** protocol semantic changes; product financial authority; external-effect bypass

## Objective
Define the actual PaySwap runtime topology and explicit development, test/CI, sandbox, staging and production boundaries from the repository's real entrypoints.

## Acceptance
- Every deployed component maps to an actual repository entrypoint/module.
- Web/API, worker, scheduler, persistence, queue, evidence storage and adapter boundaries are explicit.
- Sandbox/demo cannot reach production financial effects without separately authorized production configuration.
- Runtime ownership of protocol authorities is explicit.
- Configuration and secret boundaries are documented and validated.
- Architecture and deployment documentation agree with the implementation.
- Static/configuration verification passes.

## Required evidence
Topology proof, environment-isolation proof, configuration validation and one production-like startup/readiness check.

## Stop conditions
Contradictory runtime ownership, missing authority boundary, unsafe environment crossing, or any need to alter frozen protocol semantics.
