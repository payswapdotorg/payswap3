# PC-006 — Deployment and provider-binding contract

**Status:** BLOCKED
**Depends on:** PC-005

## Files

- deployment contract files under `deploy/` and `spec/deployment/` that directly describe the existing Next.js package
- console deployment verification scripts/evidence under existing repository conventions
- provider-binding tests

## Deliverables

Define the console-specific deployment contract without changing the existing application topology. Verify that the console ships as part of the current Next.js application/package.

Separate repository verification from deployment verification. Build/typecheck success is not production proof.

At execution time, verify actual provider connections before making claims about Vercel, database, queue, Cloudflare, or observability integrations. The plan must record unbound providers explicitly when access is absent rather than creating fake bindings.

Add checks for environment configuration, exact package identity, route availability, and provider readiness where evidence exists.

## Verification

Run the repository build/typecheck suite and deployment-contract checks. Record the exact candidate revision, package identity, environment requirements, and provider-binding evidence.

## Stop

Stop when deployment evidence cannot be obtained from the actual provider, when a deployment change would bypass the existing topology, or when a local result is being presented as production proof.
