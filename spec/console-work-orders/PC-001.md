# PC-001 — Console foundation, contracts, and governance

**Status:** DISPATCHABLE
**Depends on:** none
**Parallelism:** serial first wave

## Goal
Freeze the implementation contracts needed by all later console work without changing financial authority or closed completion records.

## Owned files

Create or modify only these surfaces:
- `src/lib/console/` contracts, authority mappings, environment context, and role policy
- `src/app/console/` route-group scaffolding only; no feature views
- `src/app/api/console/` boundary scaffolding only
- `src/components/console/` shared console primitives only
- `spec/console/` reconciliation and route-role matrices
- console-specific tests under existing repository test conventions

Do not modify protocol authority implementations, existing role surfaces, closure records, or deployment provider claims.

## Deliverables

1. Server-side principal/role policy with fail-closed authorization.
2. Server-derived environment context; client input cannot select production/test.
3. Stable DTO conventions for `UNKNOWN`, `WAITING`, `IN_PROGRESS`, `FAILED`, `SUCCEEDED`, and `ACTION_REQUIRED`.
4. Authority metadata shape for every consequential field/view.
5. Shared console route/module registry matching the approved information architecture.
6. Reconciliation matrix scaffold covering payment, checkout, capability, operations, and developer request views.
7. Governance validation preventing console code from importing or writing financial persistence directly.

## Verification battery

Run `npm run typecheck` and `npm run build`. Add focused tests proving unauthorized roles fail closed, environment is server-derived, unavailable authority data remains UNKNOWN, and DTOs do not invent business state.

## Worker stop conditions

Stop and return to Tech Lead if an authority, persistence model, role source, or environment source is unclear; if a new financial state must be introduced; or if an owned-file change requires a closed-program record mutation.
