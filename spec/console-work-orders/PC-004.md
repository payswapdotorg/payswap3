# PC-004 — Composed console views

**Status:** BLOCKED
**Depends on:** PC-002, PC-003

## Files

- `src/app/console/` feature routes below the shell
- `src/components/console/views/`
- focused console view tests and accessibility evidence

## Deliverables

Compose Overview, Payments list/detail, Checkout sessions/configuration/test, Accounts, Capabilities, and Operations views from PC-003 DTOs only.

Payment detail must expose authoritative amount, relationships, timestamp, rail/effect, reference, timeline, canonical object, owner/authority, execution receipt, and reconciliation evidence when those fields exist. Business outcomes must distinguish succeeded, failed, UNKNOWN, waiting, and infrastructure/request failure.

Checkout test actions must use the existing protocol/runtime path and an explicitly server-derived environment. No console-local simulator may masquerade as real protocol execution.

Capability and account views are projections; availability must come from authoritative runtime/capability state.

Operations is read-mostly and must preserve the established health/recovery taxonomy.

## Verification

Run typecheck/build plus role isolation, UNKNOWN semantics, responsive layout, keyboard/focus, accessible state announcement, and no-horizontal-overflow checks. Verify all consequential views against the reconciliation matrix.

## Stop

Stop if a view requires inventing financial truth, bypassing PC-003, or exposing another role's data.
