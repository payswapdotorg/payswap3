# PC-003 — Console API and read models

**Status:** BLOCKED until PC-001 is merged
**Depends on:** PC-001
**Parallel:** may run beside PC-002 after PC-001

- `src/app/api/console/`

- `src/lib/console/authority/`

## Deliverables

Build the thin server-side composition boundary for console reads. It must select the current principal and environment, call existing authoritative protocol/runtime and operational read sources, normalize responses into stable DTOs, preserve UNKNOWN, and attach source metadata where useful.

Do not create a second payment identifier, balance store, settlement state machine, finality authority, or direct financial persistence writer.

Preferred sources are the existing `/api/health`, `/api/ready`, `/api/protocol`, `/api/mediation`, and `/api/shell` boundaries and their underlying runtime composition points. Add adapters only where the existing implementation does not expose a required read safely.

## Verification

Test role filtering, environment isolation, DTO schemas, UNKNOWN propagation, and source metadata. Run `npm run typecheck` and `npm run build`.

## Stop

Stop when a required view cannot be traced to an owning authority or would require a new financial store/state machine.
