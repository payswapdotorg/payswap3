# PC-007 — Production-like verification, evidence, and closure

**Status:** BLOCKED
**Depends on:** PC-006

## Files

- verification scripts under existing `scripts/` conventions
- console evidence under `spec/console/` and existing evidence conventions
- console closure record and reconciliation report
- console program state record

## Deliverables

Verify one exact release revision through the complete console contract.

Required journeys:

1. customer payment/activity visibility;
2. merchant payment and checkout visibility;
3. provider capability/activity visibility;
4. operator operations, UNKNOWN, recovery, and reconciliation views;
5. role/deep-link isolation;
6. developer credential/webhook/logging paths;
7. documentation links;
8. sandbox/test versus production environment separation.

Inject representative unavailable-authority and delayed-operation cases. The UI must preserve UNKNOWN or waiting semantics and must not convert transport failure into a business verdict.

Run static/conformance, console contract, integration, UX/accessibility, and deployment evidence batteries from the design. Record exact revision, package identity, test outputs, role matrix, reconciliation mappings, and provider evidence.

## Closure rule

PC-007 is not complete when tests pass alone. Completion requires Tech Lead reconciliation plus explicit Architect approval. Record PC completion only in the console program state; do not modify the closed system-completion records.

## Stop

Stop on any unreconciled consequential field, role leakage, authority bypass, protected-data exposure, unexplained UNKNOWN semantics, invented provider claim, or release-evidence mismatch.
