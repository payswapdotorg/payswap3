# Product-layer versioning

Product/UI/runtime documents may use independent product-layer version labels. A label such as `v0.2` is not a PaySwap protocol architecture version and must never be interpreted as replacing `spec/architecture/v0.1/`.

The product layer may evolve its information architecture, interaction model, workflow contracts and runtime handoff documents while preserving protocol authority boundaries.

Any change to protocol-visible semantics requires the Architecture Change Request process and a new immutable protocol architecture version.
