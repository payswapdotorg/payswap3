UI-001 — Product foundation: application shell, navigation grammar, and state display primitives

Status: MERGED — f934a76 (PR #6)
Depends on: none (first product work item; executes against a base repository state in which the frozen protocol architecture, spec/architecture/v0.1/, is present)
Owned surfaces: application shell and root layout; the single shared navigation grammar; state display primitives (SUCCEEDED, FAILED, UNKNOWN, WAITING, IN_PROGRESS, ACTION_REQUIRED); environment awareness signal (sandbox vs production); role-scoped navigation scaffold for the five roles; shell-level mapping records
Forbidden: protocol semantics; financial authority; bypassing protocol authorization; presenting sandbox as production; any financial-state rendering (this item introduces none)

Objective

Materialize the product foundation that every later surface mounts into: one application shell with a single navigation grammar, the explicit state and UNKNOWN display primitives required by the UX contract, a persistent sandbox/production environment signal, and role-scoped navigation scaffolding — with deliberately zero financial semantics.

Acceptance
One navigation grammar exists, implemented once in the shell and consumed by every route and surface; no surface-local navigation paradigm is present (P1).
The breakpoint set is defined once, documented, and shared (P10).
State display primitives render SUCCEEDED, FAILED, UNKNOWN, WAITING, IN_PROGRESS, and ACTION_REQUIRED as visually and semantically distinct components; no state is signaled by color alone (P4, P5, P9).
UNKNOWN renders as unknown — distinct label, distinct visual, plain-language explanation — never styled, worded, or logged as success or failure (P5).
WAITING primitives always carry: what is waiting, why, what happens next, and the available actions or an explicit "no action is available yet" (P6).
Render conditions are distinct from outcomes: a failed fetch renders UNKNOWN (availability unknown), not FAILED (P4, P5).
The environment signal is always visible, derived exclusively from explicit configuration, and not spoofable by user content, URL parameters, or client state (UX contract Section 10).
Role-scoped navigation exposes only role-appropriate entries for customer, merchant, provider, operator, and administrator; unknown or unauthenticated visitors get least visibility (P8).
No financial semantics anywhere in the shell: no balances, no settlement or finality language, no protocol state invention (N1, N2).
Accessibility baseline holds: semantic landmarks, full keyboard operability, visible focus, labeled controls (P9).
Shell-level consequential states (environment, role availability) carry complete mapping records answering the nine reconciliation questions (UX contract Section 8).
Required evidence

Shell rendering proof across the shared breakpoints; state-primitive matrix rendering proof including the UNKNOWN and fetch-failure cases; environment-signal derivation and anti-spoofing proof; role-routing matrix proof; mapping-record review for shell-level consequential states; static verification.

Stop conditions

Any need to define or alter protocol semantics; any requirement for the shell to compute or originate financial truth; an environment signal not derivable from explicit configuration; a role model requiring UI-invented authority; any primitive that cannot distinguish UNKNOWN from FAILED.
