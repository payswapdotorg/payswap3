UI-003 — Merchant checkout surface

Status: PLANNED
Depends on: UI-002
Owned surfaces: merchant checkout flow (offer/quote presentation, explicit accept and decline, consequential state presentation); merchant navigation entries; mapping records for checkout consequential states
Forbidden: protocol semantics; financial authority; bypassing protocol authorization; obscured-condition or pre-selected commitment patterns; silent state mutation

Objective

Materialize the merchant-side checkout surface: present the offer or quote with complete, plain-language consequences; capture an explicit accept or decline; and present the resulting states explicitly — including UNKNOWN — with the merchant role seeing only merchant surfaces.

Acceptance
Offer/quote presentation is complete and consequence-first: amounts, conditions, and obligations are visible before any commitment; nothing decision-relevant is collapsed (P2, P3).
Accept and decline are explicit, distinct, single-intent actions; neither is pre-selected; both route through protocol authorization (N3).
Post-action states are explicit via the shared primitives: acknowledged, declined, failed with reason, or UNKNOWN with its reconciliation path (P4, P5, P6).
No financial truth is computed or originated UI-side; every consequential state maps to a protocol object/state with an owning authority via complete nine-question mapping records (N1, UX contract Section 8).
The evidence trail is reachable for consequential checkout outcomes (P7).
The merchant sees only merchant surfaces; customer, provider, operator, and administrator surfaces are invisible; deep links are role-checked (P8).
The surface consumes the shared navigation grammar and breakpoint set (P1, P10).
Accessibility baseline holds: keyboard operability, labeled controls, no color-only state signaling (P9).
Required evidence

Checkout accept/decline workflow evidence across outcomes; checkout state matrix rendering evidence including UNKNOWN; mapping-record review; role-visibility proof; accessibility and responsive spot evidence on the surface.

Stop conditions

Any requirement for the checkout surface to originate or mutate financial state outside protocol authorization; any obscured-condition or pre-selected commitment pattern; any consequential state without a mapping record; any UNKNOWN masked as success or failure.
