UI-004 — Provider and capability surface

Status: MERGED — 35ef9fe (PR #12)
Depends on: UI-002
Owned surfaces: provider capability/eligibility presentation surface (read-only); provider navigation entries; mapping records for capability consequential states
Forbidden: protocol semantics; financial authority; bypassing protocol authorization; UI-side capability, eligibility, or routing computation; rendering UNKNOWN as a definitive value

Objective

Materialize the provider-facing capability surface: a strictly read-only presentation of capability and routing truth owned by protocol authorities, with explicit states including UNKNOWN when capability cannot be authoritatively determined, and the provider role seeing only provider surfaces.

Acceptance
The surface is strictly read-only presentation of authoritative protocol truth; the UI computes no capability, eligibility, or routing decision (N1, P11).
Each capability item presents its authoritative state via the shared primitives; indeterminate renders as UNKNOWN with its reconciliation path — never as failure or success (P4, P5).
Unavailable authoritative sources render UNKNOWN (availability unknown), distinct from outcome failure (P4, P5).
Every consequential capability state carries a complete nine-question mapping record (UX contract Section 8).
The provider sees only provider surfaces; deep links are role-checked on direct entry (P8).
Progressive disclosure: headline capability status first, composition and detail one deliberate step away (P3).
The surface consumes the shared navigation grammar and breakpoint set (P1, P10).
Accessibility baseline holds (P9).
Required evidence

Capability surface rendering evidence across authoritative states including UNKNOWN; mapping-record review; role-visibility proof; accessibility and responsive spot evidence on the surface.

Stop conditions

Any requirement to compute capability or eligibility UI-side; any pressure to render UNKNOWN as success, failure, or a definitive value; capability semantics that contradict the frozen protocol architecture; any consequential state without a mapping record.
